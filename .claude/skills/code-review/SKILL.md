# Code Review

审查当前分支/暂存的改动（默认 `git diff` 主分支与当前分支，或用户指定范围）。按以下维度逐项检查，输出问题清单（按严重程度排序）。

## 规范检查（依据 `.claude/rules/global.md` + 对应目录专属规则）

1. **命名与语法**：文件命名、变量/函数语义化、`==` 误用等，统一以 `global.md` 文件命名总表为准，不在此重复罗列
2. **组件**：SFC 顺序；Props 是否用 interface + withDefaults；样式是否 scoped；单文件是否 >800 行
3. **API**：是否绕过 `request.ts` 直接 axios；接口命名是否 `Using{Method}`；是否 `.then()` 链式调用；异常是否静默失败
4. **类型**：是否无理由使用 `any`（豁免条件见 `global.md`）；是否用 `@/` 别名
5. **路由**：懒加载；name 语义化；需要鉴权是否配 `meta.access`；新增页面是否在 `routes.ts` 登记
6. **注释与日志**：导出函数 JSDoc；是否残留 `console.log`、无主 TODO、垃圾注释

## 缺陷检查

- 重复代码（可抽 hook/组件/工具函数）
- 明显 bug：空值/未定义访问、死代码、错误的状态更新、卸载后异步回写
- 资源泄漏：事件监听、定时器、WebSocket 未清理
- 改动超出单文件 500 行的建议线（提示拆分）

## 输出格式

```
## 严重问题（必须修）
- [文件:行] 描述 + 原因 + 修复建议

## 建议改进
- ...

## 符合规范 ✓
- 简要列出符合项（如无问题则整体通过）
```

> 提示：若改动代码与项目周边现有代码风格不一致（且本规则未明确覆盖），请提示开发者判断是否需要更新规则。

不修改代码，只输出审查结论；用户确认后再做修复。
